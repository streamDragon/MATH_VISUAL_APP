# Vizy — דוח השדרוג

נבנה פיילוט ממשי ללמידה חזותית בטלפון, בעברית ובאנגלית. הוא מבוסס על המחשות ותוכן מוכנים מראש, כך שאין הוצאה על מודל AI לכל פעולה של תלמיד.

## מה נבנה

| רכיב | מצב |
|---|---|
| ממשק מובייל כהה, ניווט תחתון ומעבר לאנגלית | עובד בדפדפן; ללא SDK או פונט חיצוני במסלול החדש |
| בנק התחלתי | 24 פעילויות מקוריות, 12 חינמיות ו־12 במסלול מורחב |
| המחשות | ישר ושיפוע, הזזת פרבולה, חיתוך ישרים, משולש ופיתגורס, הסתברות ונגזרת |
| בניית ייצוג פנימי | ניבוי → חקר ציור → תשובה → העברה לנתונים חדשים בלי ציור; אפשר לבקש לראות ציור |
| התקדמות | 40 נקודות לפעילות פעם אחת; חזרה אינה מעניקה שוב נקודות |
| משוב | צלילי הצלחה, אפקט חלקיקים, השתקה וכיבוד reduced motion |
| דמויות ומפה | שלושה אווטארים מקוריים ומסלול הרים עד פרח בפסגה |
| בקשות לחגי | טקסט/תמונה, טיוטה מקומית, קבלה רק אחרי מזהה מהשרת, תור ופרסום מענה |
| ניהול תוכן | יבוא JSON, בדיקת תשובות מול מנוע מתמטי והרשאת מנהל בשרת |
| כיתה וקבוצת solo | סכימת שרת והרשמה אמיתית; solo עד עשרה אחרים באותה כיתה ובטווח השלמות דומה |
| תחרות | אימות השלמות בשרת; בונוס 20 לראשון שמסיים את מסלול הקבוצה |
| מנויים | מסכי חינם/מורחב/כיתה, והגבלת תוכן ב־RLS; אין סליקה פעילה |
| כלי הכנת חומר | חילוץ טיוטות מקובץ טקסט/HTML/DOCX/PDF עם מקור; נדרשת בדיקה והפקת המחשה |
| ללא רשת | אתגרים חינמיים עובדים אחרי טעינה ראשונה ושמירת המטמון |

הבנק המקורי אינו מכסה את כל תוכנית הלימודים. הנושאים והשאלות דורשים בדיקה של חגי מול השכבה, המסלול ורמת היחידות. לא סופקו ספרים או קישורי שאלות מטיק־טק לייבוא; אין טענה שחומר מאתרים אלה נאסף.

## מה דורש השלמה בחשבונות שלך

קוד השרת נבדק מקומית, אך מיגרציית Supabase, הרשאת הניהול של חגי וכתובות הכניסה לא הוגדרו בחשבון החי כאן. בדיקת החיבור לפרויקט החי הסתיימה ב־timeout; לא הוכחה מוכנותו. עד הפעלה ובדיקה בחשבונות אמיתיים, אין להציג בקשות, קבוצות או הרשאות מנוי כפעילים. [הוראות לסוכן](REMOTE_BACKEND_SETUP.md).

קריינות הוכנה כחיבור לקבצים. ה־manifest ריק: אין עדיין קולות חדשים שהופקו מ־Kokoro. אין גישה להתקנה במחשב שלך. [פרומפט לסוכן עם גישה למחשב](KOKORO_REMOTE_HANDOFF.md).

סליקה, חידוש וביטול מנוי אינם ממומשים. מסך המסלולים מסביר שאין חיוב פעיל. יש לחבר ספק תשלומים ולאמת webhook בשרת לפני מכירה. חשבון Supabase עם מפתח ציבורי אינו הרשאת בעלים להפעלת הסכימה.

הבנק הראשוני נמצא במאגר GitHub ציבורי. ההגבלה באפליקציה מבוססת שרת, אבל המקור הציבורי אינו תוכן סודי. תוכן מסחרי עתידי יש לשמור במאגר פרטי. התקדמות המסלול האישי נשמרת במכשיר; השלמות קבוצתיות ובונוסים נשמרים בשרת ומוצגים כיתרה מאומתת נפרדת. אין עדיין סנכרון מלא של המסלול האישי בין מכשירים.

## בדיקות

עברו 24 בדיקות מנוע/שירות/מסד נתונים, 4 בדיקות ייבוא ו־30 בדיקות דפדפן; גם build וולידטורי השאלות הקיימים עברו.

סקירת קוד נוספת הושלמה. תוקנו פתיחת מענה חדש ללא רענון, הצגת משימות הקבוצה, יתרת בונוס מאומתת לאחר כניסה מחדש, ניסוח תיווך לפרבולה יורדת וחיפוש לפי תוכן באנגלית.

המנוע והבנק נבדקו מספרית, כולל שברים, פסיק עשרוני, ערכים לא תקינים, חיתוך ישרים מקבילים ומניעת ניקוד חוזר. סכימת PostgreSQL נבדקה עם RLS: בידוד בקשות, מניעת הענקת מנוי עצמית, חסימת מנהל לא מורשה, בדיקת תשובות בשרת, משתתפים ללא מזהי חשבון ותקרת 11 תלמידים. אפליקציית הלמידה נבדקה ב־Playwright על Chromium במחשב ובאמולציית iPhone 13, כולל offline.

Safari/WebKit ומכשירי Android/iPhone פיזיים לא נבדקו בסביבה הזאת. גרסת Chromium הניידת בסביבה סגרה לעיתים את התהליך אחרי סגירת העמוד האחרון. נוסף בידוד ברמת סביבת הבדיקות: כל בדיקה מקומית משתמשת בתהליך דפדפן חדש. בדפדפני Playwright רגילים ב־CI נשמר מנגנון הבדיקות הרגיל. הנחיות ההרצה מופיעות ב־README. הפעלה על חשבונות Supabase חיים וגבייה דורשות בדיקות נפרדות אחרי ההגדרה.

## איך להתקדם להכנסות בתקציב קטן

1. להתחיל בפיילוט עם מורה אחד וכיתה אחת. למדוד הצלחה בשאלת העברה לפני ואחרי שימוש, לצד שימוש חוזר בפועל. לא להסתפק במספר כניסות או בניקוד.
2. להשאיר מסלול חינמי שימושי. המסלול המורחב יכול למכור סדרת תרגול מסודרת, מאגר גדל ומכסת בקשות אנושיות. מסלול כיתה יכול למכור משימות שבוחר המורה ומעקב קבוצתי.
3. להפריד בין המשתמש לבעל התקציב: תלמידים לומדים, מורה מוביל את הפיילוט, הורים או בית הספר משלמים. להציג להורים דוגמת הבנה והעברה, ולמורה זמן הכנה שנחסך.
4. למדוד זמן הכנה של המחשה וטיפול בבקשה. היעד של 24 שעות דורש מכסה שמתאימה לזמן שלך; כיום הקוד מגדיר שתי בקשות בחודש בחינם ועשר למשתמש עם גישה מורחבת. אלה ברירות מחדל לפיילוט, לא מחירון או הבטחת שירות.
5. לבחור מחיר אחרי פיילוט ושיחות עם רוכשים. לא נבדקו נכונות תשלום, עלות תמיכה, יחס המרה או רווחיות, ולכן אין תחזית הכנסה מוכחת.
6. להשתמש באנגלית לניסוי קטן עם מורה דובר אנגלית. להרחיב אחרי התאמת ניסוחים, שכבות ותוכן לתוכנית המקומית וקבלת משוב. מעבר שפה כשלעצמו אינו הוכחת ביקוש.

## רשימת שיפורים להמשך

- להרחיב שאלות לפי יחידות ורמות, כולל טריגונומטריה ממשית, גאומטריה והוכחות; כיום המשולשים עוסקים בפיתגורס.
- להוסיף סנכרון התקדמות בין מכשירים ודוח מורה של קשיים לפי רעיון.
- להפעיל קריינות עברית ואנגלית, להוסיף אנימציות תנועה לדמויות ולבחון אותן בטלפונים חלשים.
- להוסיף מעקב זמן טיפול לבקשה ותהליך טיפול בבקשת מחיקת מידע אצל המפעיל.
- לשפר התאמת קבוצות באמצעות הצלחה בשאלות העברה; כיום ההתאמה משתמשת בשכבה ובכמות השלמות מאומתות.
- להוסיף תחרות שיתופית ומטרות כיתתיות לצד תחרות לראשון; לבדוק שמתקדמים בהבנה ולא רק ממהרים.
